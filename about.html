About The Family Table

A personal collection of global, seed- and legume-forward recipes — built for real weeks, low-energy days, and cooking for one. This page is both an introduction to the site and a reference for keeping it up to date.

What this site is

The Family Table is a home for recipes that lean on seeds, beans, and plant protein — gathered from a lot of different kitchens and traditions, organized so they're easy to find on a weeknight. Search and tag filtering live on the homepage; the Meal Planner turns any set of selected recipes into a single grocery list, grouped by where each ingredient actually lives in the house.

How it's built

All recipe content lives in one file, recipes-data.js. Both the recipe pages and the planner read from it directly. There are no separate files per recipe and nothing is fetched from markdown — that was an earlier approach that GitHub Pages blocked, so the whole site was rebuilt around this single data file instead.

That means editing or adding a recipe only ever touches one or two files, and never recipe.html, planner.html, or style.css.

Editing an existing recipe

  1. Open recipes-data.js in GitHub.
  2. Find the recipe by its id — e.g. "muhammara": {
  3. Edit whatever you need — title, description, ingredients, steps, notes — and commit.

That's the whole process. The recipe page and the grocery planner both pick up the change automatically.

Ingredient format

Each ingredient is one line:

{ "amount": 1, "unit": "cup", "name": "walnuts, lightly toasted", "location": "Pantry", "category": "Nuts & Seeds" }
FieldNotes
amountA plain number. Halves and quarters are decimals — 0.5, 0.25, 0.333 — not fractions. Displays back as ½, ¼, ⅓ automatically.
unite.g. "cup", "tbsp", "tsp", "oz", "lb", "can". Use null for counted items (e.g. "3 garlic cloves") — put the counting word in name instead.
nameThe ingredient description, including prep — e.g. "garlic cloves, minced".
locationWhere it lives in the house. Exactly one of: Fridge, Freezer, Pantry, Counter, Spice Rack.
categoryThe subgrouping used in the grocery planner — see below. Reuse one exactly rather than inventing a new one.
No real amount, like "salt and pepper to taste"? Set "amount": null.

Plain water or anything that shouldn't appear on a grocery list? Add "skip": true to that ingredient and the planner will ignore it. Search recipes-data.js for existing examples in the tahini dressing or the granolas.

Steps format

{ "title": "Sauté the onion", "text": "In a wide pot..." }

Steps are just an ordered array — add, remove, reorder, or reword freely. title shows as the bold step label; text is the instruction body.

Notes format

notes is a single string. For multiple paragraphs, separate them with \n inside the string — each becomes its own paragraph on the page.

Adding a brand new recipe

Two steps — one in the data file, one on the homepage.

1. Add the recipe to recipes-data.js

Copy an existing recipe entry as a template and give it a new id — short, lowercase, hyphenated (e.g. "lentil-koftas"). This id becomes the URL: recipe.html?r=lentil-koftas.

"your-new-id": {
  "title": "...",
  "description": "...",
  "origin": "...",
  "time": "...",
  "servings": 4,
  "instant_pot": false,
  "section": "Dinner",
  "tags": ["Dinner", "Vegetarian"],
  "ingredients": [ /* ... */ ],
  "steps": [ /* ... */ ],
  "notes": "..."
}

Don't forget the comma after the closing brace if it's not the last entry in the file. section should be one of: Breakfast, Stews, Sauces & Dips, Beans, Dinner.

2. Add a card to index.html

Find the section matching your recipe (search for <!-- DINNER -->, for example), copy an existing <a class="recipe-card"> block within it, and update:

  • href="recipe.html?r=your-new-id" — must match the id from step 1
  • the origin, title, and description text
  • data-tags — space-separated tags used by the tag filter buttons
  • data-search — space-separated keywords used by the search box
  • the time and tag pills in card-footer

That's it — the recipe page itself needs no separate file or edit; it looks up whatever id is in the URL automatically.

Adding photos

Every recipe can have a photo — a hero image at the top of the recipe page, and optionally a matching thumbnail on its homepage card. Neither is required; recipes with no photo look exactly as they do now.

1. Add the image file to the repo

Create an images folder in the repo root if it doesn't exist yet, and upload the photo there. A few things that keep the site fast and looking good:

  • JPG or WEBP, not PNG — photos compress much better as JPG
  • Resize to around 1600px on the long edge before uploading. Straight-from-phone photos are often 3000px+ and needlessly large
  • Name the file to match the recipe id, e.g. muhammara.jpg — easy to find later

2. Add the image field to recipes-data.js

Add one line to that recipe's entry:

"image": "images/muhammara.jpg",

This alone puts the photo at the top of that recipe's page.

3. (Optional) Add it to the homepage card

In index.html, find that recipe's card and add an <img> as the very first thing inside the <a class="recipe-card"> tag, before the card-accent div. Give it the same category class the accent div uses (stew, sauce, bean, dip, breakfast, or dinner) so the card's left border color still matches its section:

<a class="recipe-card" href="recipe.html?r=muhammara" ...>
  <img class="card-photo dip" src="images/muhammara.jpg" alt="Muhammara">
  <div class="card-accent dip"></div>
  <div class="card-body">...</div>
</a>
Photos are entirely optional, on both the recipe page and the card, and independent of each other — you can add a hero photo without a card thumbnail, or vice versa. Recipes with no image field are unaffected and keep looking exactly as they do now.

A note on the grocery planner

The planner combines ingredients across recipes by matching on name + unit. If two recipes call the same ingredient slightly different things — "garlic cloves, minced" vs. "garlic clove, minced" — they won't merge into one line; they'll just appear as two separate entries on the list. Not a big problem, just worth keeping half an eye on for common ingredients (garlic, onion, olive oil, salt) when writing new recipes. Reusing the exact wording from an existing recipe when it's the same ingredient keeps the list clean.
